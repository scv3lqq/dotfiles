# How to be productive: buffers, oil, yazi, telescope

Краткий гайд, как эти штуки сочетаются в моём workflow. Каждый инструмент решает
свою задачу — важно не путать их и не пытаться сделать одним то, что лучше
делает другой.

```
┌────────────┬───────────────────────────────────────────────┐
│ buffers    │ что уже открыто в этой сессии Neovim          │
│ telescope  │ найти что-то и открыть (файл / буфер / текст) │
│ oil        │ редактировать дерево файлов прямо в буфере    │
│ yazi       │ навигация по ФС снаружи nvim, как TUI         │
└────────────┴───────────────────────────────────────────────┘
```

---

## 1. Буферы (buffers)

Буфер — это **открытый в памяти Neovim файл**. Не вкладка, не окно. Открыл файл
— получил буфер. Закрыл окно — буфер всё ещё жив, пока не сделаешь `:bd`.

### Базовое

| Команда | Что делает |
|---|---|
| `:e path/to/file` | открыть файл (создаст буфер) |
| `:ls` / `:buffers` | список всех буферов |
| `:b <part>` | переключиться на буфер по части имени (с Tab-автодополнением) |
| `:bn` / `:bp` | следующий / предыдущий буфер |
| `:bd` | закрыть текущий буфер |
| `:bd!` | закрыть, даже если есть несохранённые изменения |
| `:%bd\|e#` | закрыть все буферы кроме текущего |
| `<C-^>` | прыгнуть на предыдущий буфер (very useful) |

### В моём конфиге

- `<C-p>` — список буферов через Telescope (`telescope.lua:30`).
- `<leader>fb` — то же самое (`telescope.lua:25`).

Внутри списка буферов Telescope:
- `<C-d>` — закрыть выделенный буфер прямо из пикера.
- Enter — открыть.

### Workflow

1. Открыл проект → Telescope `<leader>ff` → выбрал файл → буфер №1.
2. Прыгнул в другой файл через `gd` / `<leader>ff` → буфер №2.
3. Туда-сюда: `<C-^>` или `<C-p>` (Telescope buffers).
4. Закончил с файлом → `:bd`, чтобы не засорять список.

> **Главное правило**: окно ≠ буфер. Закрытие окна (`<C-w>q`) не закрывает
> буфер. Хочешь убрать файл из памяти — `:bd`.

## 2. Telescope — fuzzy finder для всего

Telescope — это **«найди что угодно»**. Файл, текст в файлах, открытый буфер,
символ в коде, диагностику LSP, недавно открытое. Один UI на всё.

### Кейбинды (`telescope.lua`)

| Кейбинд | Что ищет |
|---|---|
| `<leader>ff` | файлы в текущем проекте (`find_files`) |
| `<leader>fg` | live grep по всему проекту (нужен `ripgrep`) |
| `<leader>fb` / `<C-p>` | открытые буферы |
| `<leader>fr` | недавно открытые файлы (`oldfiles`) |
| `<leader>fh` | help-теги Neovim |
| `<leader>fd` | LSP-диагностики (ошибки, warnings) |
| `<leader>fs` | символы в текущем файле (LSP) |

### Внутри пикера

| Кейбинд | Действие |
|---|---|
| `<C-j>` / `<C-k>` | вниз / вверх по списку |
| `<CR>` | открыть в текущем окне |
| `<C-x>` | открыть в горизонтальном сплите |
| `<C-v>` | открыть в вертикальном сплите |
| `<C-t>` | открыть в новой вкладке |
| `<C-u>` / `<C-d>` | скролл preview |
| `<C-q>` | отправить весь результат в quickfix |
| `<Esc>` (norm) / `<C-c>` (insert) | закрыть пикер |

### Когда что использовать

- **Знаю имя файла** → `<leader>ff` + 2–3 буквы → Enter.
- **Знаю слово/фразу из кода, но не файл** → `<leader>fg` → введи строку.
- **Хочу вернуться к недавнему** → `<leader>fr` (oldfiles переживает рестарт).
- **Прыгаю между уже открытыми** → `<C-p>`.
- **Где ошибка в проекте?** → `<leader>fd`.
- **Куда уехал этот символ в файле?** → `<leader>fs`.

> Live grep (`<leader>fg`) — это поиск **по содержимому**, а find files
> (`<leader>ff`) — по **именам файлов**. Это самая частая путаница у новичков.

## 3. Oil — файловый менеджер как буфер

[oil.nvim](https://github.com/stevearc/oil.nvim) показывает директорию как
обычный текстовый буфер: строки = файлы. Хочешь переименовать — правишь строку,
`:w`. Хочешь удалить — удаляешь строку, `:w`. Перенести — вырезаешь и
вставляешь в другой oil-буфер.

### Открытие

- `-` (минус) в нормальном режиме — открыть oil в директории **текущего файла**
  (`oil.lua:8`).
- `:Oil` — открыть oil в `cwd`.
- `:Oil path/to/dir` — конкретный путь.

В конфиге `show_hidden = true`, так что dot-файлы видно сразу (`oil.lua:6`).

### Базовая навигация внутри oil

| Кейбинд | Действие |
|---|---|
| `<CR>` | войти в директорию / открыть файл |
| `-` | подняться на уровень выше |
| `_` | прыгнуть в `cwd` |
| `<C-s>` | открыть выбранное в вертикальном сплите |
| `<C-h>` | открыть в горизонтальном сплите |
| `<C-p>` | preview под курсором (toggle) |
| `<C-c>` | закрыть oil |
| `g?` | help — показать все кейбинды |
| `gx` | открыть файл системным приложением (`open`) |
| `g.` | toggle скрытых файлов |

### Редактирование как буфер — главная киллер-фича

1. **Создать файл/папку** — допиши строку, папка с `/` на конце. `:w` создаст.
2. **Переименовать** — измени имя в строке, `:w`.
3. **Удалить** — удали строку (`dd`), `:w`. Oil спросит подтверждение.
4. **Переместить** — `dd` в одном oil-буфере, `p` в другом, `:w`.
5. **Скопировать** — `yy` + `p`, потом изменить имя если в той же папке, `:w`.

Можно открыть **два oil-буфера в сплитах** (`:vs | Oil ~/other`) и
перетаскивать файлы между ними как в двухпанельном менеджере.

### Workflow

- Быстро глянуть «что лежит рядом с этим файлом» → `-`.
- Массовое переименование (10 файлов) → `-` → `:%s/old/new/g` → `:w`.
- Создать сразу несколько файлов в новой папке → `-` → допиши строки → `:w`.

## 4. Yazi — TUI-навигатор снаружи Neovim

[yazi](https://yazi-rs.github.io/) — это отдельная программа (Rust), запускается
в терминале как `yazi`. Когда нужен **полноценный двухпанельный файловый
менеджер с preview, поиском, bulk-операциями** — берёшь yazi, не oil.

Конфиг: `yazi/yazi.toml`. Сейчас там одно правило: `nvim` открывается как
блокирующий редактор для текстовых файлов / json / toml / yaml.

### Базовая навигация

| Кейбинд | Действие |
|---|---|
| `h` / `j` / `k` / `l` | влево (вверх по дереву) / вниз / вверх / вправо (войти) |
| `H` / `L` | назад / вперёд по истории директорий |
| `g g` / `G` | в начало / конец списка |
| `<Space>` | выделить (mark) файл |
| `v` | visual select |
| `<Esc>` | снять выделение |
| `q` | выйти |
| `Q` | выйти и `cd` в текущую директорию yazi (нужен shell wrapper) |

### Операции с файлами

| Кейбинд | Действие |
|---|---|
| `o` / `<Enter>` | открыть (через правило из `yazi.toml`) |
| `O` | открыть с выбором приложения |
| `a` | создать файл (`a name`) или папку (`a name/`) |
| `r` | переименовать |
| `d` | вырезать (cut) выделенное |
| `y` | копировать (yank) |
| `p` | вставить |
| `P` | force paste (перезаписать) |
| `x` | в корзину |
| `D` | удалить навсегда (с подтверждением) |
| `<C-z>` | suspend (потом `fg` чтобы вернуться) |

### Поиск и фильтр

| Кейбинд | Действие |
|---|---|
| `/` | поиск вперёд по именам в текущей папке |
| `?` | поиск назад |
| `n` / `N` | следующее / предыдущее совпадение |
| `f` | фильтр — оставить только matching строки |
| `s` | поиск через fd по дереву |
| `S` | поиск содержимого через ripgrep |
| `z` | прыжок через zoxide (если установлен) |

### Tabs (вкладки)

| Кейбинд | Действие |
|---|---|
| `t` | новая вкладка |
| `1`..`9` | переключиться на вкладку N |
| `[` / `]` | предыдущая / следующая вкладка |
| `{` / `}` | переместить вкладку влево / вправо |

### Workflow

- Изучаю незнакомую часть ФС → `yazi`. Preview справа сразу показывает
  содержимое.
- Bulk-операции (скопировать 30 файлов в три разных места) → выделил
  `<Space>`, `y`, ушёл в другую папку, `p`.
- Открыть файл в nvim из yazi → `<Enter>` на текстовом файле. После `:q`
  вернёшься обратно в yazi.

> **Конфликт с Finder на macOS**: раньше Enter на папке мог триггерить Finder.
> Это починено коммитом `4e81c30` — `folder` opener убран, осталось только
> правило для редактируемых файлов.

## 5. Как они сочетаются

```
┌─────────────────────────────────────────────────────────────────┐
│ Сценарий                          → инструмент                  │
├─────────────────────────────────────────────────────────────────┤
│ Знаю имя файла                    → telescope <leader>ff        │
│ Знаю слово в коде                 → telescope <leader>fg        │
│ Прыгнуть между открытым           → <C-p> (telescope buffers)   │
│ Глянуть «что рядом», что-то       → oil (-)                     │
│   переименовать / создать                                        │
│ Изучить незнакомое дерево ФС,     → yazi (из терминала)         │
│   bulk move/copy, preview                                        │
│ Закрыть лишние файлы из памяти    → :bd / <C-d> в <C-p>          │
└─────────────────────────────────────────────────────────────────┘
```

### Типичный день

1. `tmux` → запустил `yazi` в одном пейне, нашёл проект → `Q` → `cd`.
2. `nvim .` → внутри nvim весь день: `<leader>ff`, `<leader>fg`, `<C-p>`.
3. Понадобилось переименовать пачку файлов → `-` (oil) → правки → `:w`.
4. Понадобилось скопировать ассеты из другого проекта → `:sus` (или
   `<C-z>`) → yazi → копирование → `fg` обратно в nvim.

### Чего **не** делать

- Не использовать oil как полноценный FM для bulk-операций между удалёнными
  директориями — yazi удобнее.
- Не использовать yazi для «открыть файл прямо сейчас в текущей сессии nvim» —
  это либо `<leader>ff` (telescope), либо `-` (oil).
- Не путать `<leader>ff` и `<leader>fg`: имена vs содержимое.
- Не плодить буферы бесконтрольно — раз в день `:%bd|e#` или закрытие через
  `<C-d>` в Telescope.
