# Trim noisy modules from Starship prompt

## Goal

Убрать из prompt избыточный хвост вида:

```
via 🐳 colima is 📦 v0.1.0 via 🐍 v3.14.5 took 1d2h55m54s
```

Конкретно отключить четыре модуля starship: `docker_context`, `package`,
`python`, `cmd_duration`. Это полная и постоянная отключка — без условной
логики per-directory.

Out of scope:

- Любые другие модули (`golang`, `nodejs`, `git_branch`, `directory` и т.п.).
- Глобальный `format` — он всё ещё дефолтный, перепиcывать его не нужно.
- Логика установки/симлинков, Stow, `install.sh`.
- Шелл-конфиги (`zsh/.zshrc`, `aliases.zsh`).
- Цветовая палитра, символы, шрифты, Ghostty/Tmux.

## Current behavior

`starship.toml` не задаёт глобальный `format`, поэтому используется дефолтный
порядок модулей starship. В файле сейчас только секции с `format = '(via …)'`
для языковых модулей, чтобы сделать вывод однострочным/минималистичным
(коммит `0012a0c feat(starship): switch to minimal prompt style`).

Релевантные секции в `starship.toml`:

- `[python]` (строки 101–102) — формат включает `${version}`, поэтому
  показывается `via 🐍 v3.14.5` даже без активного virtualenv.
- `[package]` (строки 89–90) — формат включает `$symbol$version`, поэтому
  показывается `is 📦 v0.1.0` для любого каталога с `package.json`,
  `Cargo.toml`, `pyproject.toml` и т.п.
- `docker_context` секции в файле нет → starship применяет дефолт, который
  показывает контекст, когда он не равен `default` (например `colima`).
- `cmd_duration` секции в файле нет → starship применяет дефолт
  `min_time = 2000` (мс). После выхода ноутбука из sleep таймер считает
  реальное wall-clock время, отсюда `took 1d2h55m54s`.

Источник по дефолтам и ключам конфига: starship.rs/config (через Context7,
`/websites/starship_rs`).

## Target behavior

После применения изменений в той же сессии и каталоге prompt не показывает
`docker_context`, `package`, `python` и `cmd_duration` ни при каких условиях.
Остальные модули (golang/nodejs/rust/git/directory/character/…) продолжают
работать как раньше.

## Files

- `starship.toml` — edit
  - Изменить секцию `[package]`: добавить `disabled = true`. `format`
    оставить как есть (на случай отката достаточно убрать одну строку).
  - Изменить секцию `[python]`: добавить `disabled = true`. `format`
    оставить как есть.
  - Добавить новую секцию `[docker_context]` с одной строкой
    `disabled = true`.
  - Добавить новую секцию `[cmd_duration]` с одной строкой
    `disabled = true`.
  - Сохранить алфавитный порядок секций, в котором они уже идут в файле
    (между `[deno]` и `[dotnet]` для `docker_context`; перед `[cobol]` уже
    есть `[cmake]`, поэтому `[cmd_duration]` должен быть между `[cmake]` и
    `[cobol]`; ср. с текущим порядком в файле).

## Constraints

- Не трогать остальные секции и их `format`.
- Не вводить глобальный `format` и не возвращать powerline-стиль.
- Не править `nvim/`, `zsh/`, `install.sh`, Stow-пакеты, лок-файлы.
- Не добавлять зависимости и не запускать `install.sh`/`stow`.
- Не переписывать комментарии и пустые строки в неизменённых секциях.
- Сохранить кодировку и одинарные кавычки (`'…'`) для строковых литералов,
  как в файле сейчас.
- Не делать коммит без явной просьбы пользователя.

## Implementation steps

1. Открыть `starship.toml`.
2. В секцию `[package]` (после `format = '(is [$symbol$version]($style) )'`)
   добавить строкой ниже:
   ```toml
   disabled = true
   ```
3. В секцию `[python]` (после её `format = …`) добавить:
   ```toml
   disabled = true
   ```
4. Добавить новую секцию для `docker_context` в правильное по алфавиту
   место (между `[deno]` и `[dotnet]`):
   ```toml
   [docker_context]
   disabled = true
   ```
5. Добавить новую секцию для `cmd_duration` в правильное по алфавиту
   место (между `[cmake]` и `[cobol]`):
   ```toml
   [cmd_duration]
   disabled = true
   ```
6. Сохранить файл. Никаких других правок.

## Tests

- Парсинг TOML: `python3 -c "import tomllib,sys;tomllib.loads(open('starship.toml').read())"` —
  должен завершиться без вывода. (Needs verification: установлен ли
  Python 3.11+ с `tomllib` локально; альтернатива —
  `taplo check starship.toml`, если `taplo` доступен.)
- Применение в живом prompt: открыть новый shell или выполнить
  `exec zsh`, перейти в каталог, в котором ранее показывались
  `via 🐳 colima`, `is 📦 v0.1.0`, `via 🐍 v3.14.5`, и убедиться, что эти
  фрагменты исчезли. (Needs verification: повторяемость зависит от того,
  есть ли у пользователя под рукой воспроизводящий каталог; ручная
  проверка.)
- Прогнать долгую команду (`sleep 3`) — `took …` не должно появиться.
- Прогнать `starship explain` в проблемном каталоге — четырёх отключённых
  модулей не должно быть в выводе.

Полный install (`./install.sh`) запускать не нужно — `starship.toml`
симлинкнут, изменения применяются сразу.

## Edge cases

- В каталоге с активным virtualenv (`$VIRTUAL_ENV`) python-модуль тоже
  будет скрыт. Это сознательная потеря — пользователь явно попросил
  убрать `via 🐍 …`. Если позже окажется нужно показывать
  `($virtualenv)` без версии, вернуть `[python]` и сменить `format` на
  показ только `$virtualenv`, а не на `disabled`.
- В Docker-проектах статус контекста больше не виден в prompt; проверять
  через `docker context show`.
- `cmd_duration` отключается полностью, а не повышением `min_time`. Это
  решает основной кейс (1d+ после sleep), но также убирает «честные»
  замеры долгих команд. Это осознанный trade-off, см. альтернативу ниже.
- Совместимость со старыми версиями starship: ключ `disabled` поддержан
  во всех модулях, отдельных миграций не требуется.

Альтернатива, если в будущем потребуется компромисс: для `cmd_duration`
вместо `disabled = true` поставить `min_time = 60000` (≥1 мин) и
`show_milliseconds = false`. Не делать в рамках этой задачи — пользователь
просил убрать.

## Acceptance criteria

- [ ] `starship.toml` содержит `disabled = true` в секциях `[package]`,
      `[python]`, `[docker_context]`, `[cmd_duration]`.
- [ ] Новые секции `[docker_context]` и `[cmd_duration]` добавлены в
      алфавитном порядке.
- [ ] Файл валидный TOML (парсится без ошибок).
- [ ] В живом prompt после `exec zsh` фрагменты `via 🐳 …`, `is 📦 …`,
      `via 🐍 …`, `took …` не появляются ни в одном проверенном каталоге.
- [ ] Никакие другие файлы репозитория не изменены.
- [ ] Коммит не создаётся, пока пользователь не попросит.

## Review notes

После реализации Claude Code должен проверить:

1. `git diff starship.toml` — только четыре блока изменены, остальные
   секции нетронуты, порядок секций сохранён.
2. `git status` — кроме `starship.toml` нет неожиданных модификаций.
3. Проверить TOML парсинг командой из секции Tests.
4. Глобальный `format` по-прежнему не задан (используется дефолт).
5. Убедиться, что для `[package]` и `[python]` старый `format` сохранён
   рядом с `disabled = true` — это упрощает откат.
6. Совпадает ли поведение с ожиданиями пользователя в живой сессии
   (визуальная проверка prompt).
